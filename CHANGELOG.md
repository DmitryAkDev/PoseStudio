# Changelog

All notable changes to the PoseStudio project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **Note on early release numbering:** the commits for two of the releases below were pushed
> with mislabeled titles — `ba4033f` ("Release 0.4.0") and `83cb038` ("Release 0.5.0") are the
> releases recorded here as **[0.3.3]** and **[0.3.4]**. Commit messages can't be rewritten on a
> public repository; this changelog and `CMakeLists.txt` (whose `project(VERSION)` stamps
> `Constants::APP_VERSION` at build time) are the authoritative version record, and releases are tagged from 0.3.0 onward.

## [0.3.13] - 2026-09-10
### Added
* **The packages now carry their license texts, and Help → About Qt shows Qt's notice.** PoseStudio is GPL v3 and is built on the Qt framework under the LGPL v3, which asks that every copy say so and include the license texts. The installer and the portable zip now place `LICENSE.txt` (GPL v3) next to the app, and a `licenses\` folder with the LGPL v3, the notices of the open-source runtimes shipped alongside Qt (ICU, Mesa's software OpenGL renderer), the Vulkan loader's license, and `NOTICES.txt` — an index naming each component, its license, and where to get the source of the exact Qt version shipped. Help → **About Qt** opens Qt's own copyright and license notice. (Developer: the texts live in `packaging/licenses/`; `release.yml` copies them and renders the Qt version into `NOTICES.txt` from `QT_VERSION`. Add a file there whenever a new redistributable joins the package.)
### Fixed
* **PoseStudio now starts on a PC that doesn't have the Visual C++ runtime installed.** The packages include the Visual C++ runtime DLLs the app and Qt need (`msvcp140`, `vcruntime140` and their companions) next to the exe. They were meant to come from `windeployqt --compiler-runtime`, which silently deployed nothing on the build machine — and would only have produced Microsoft's `vc_redist` installer anyway, which needs administrator rights the per-user setup never asks for. A machine without the runtime failed at launch with "VCRUNTIME140.dll was not found". (Developer: the stage step scans every staged binary with `dumpbin /dependents` and copies exactly the runtime DLLs they import from the same Visual Studio's redistributable folder — app-local deployment, as Microsoft documents it; the UCRT is part of Windows 10/11 and isn't shipped; windeployqt now runs with `--no-compiler-runtime` so it can never add a stray `vc_redist.x64.exe`.)
* **PoseStudio now starts on a PC whose graphics driver has no Vulkan support.** The Windows installer and portable zip ship the Khronos Vulkan loader (`vulkan-1.dll`) next to the app. Without it, a machine with no Vulkan-capable driver — a virtual machine, a fresh Windows install still on the basic display adapter, a pre-2016 GPU — refused to launch PoseStudio at all with a "vulkan-1.dll was not found" message. Now the app opens normally; the 3D viewport reports that Vulkan is unavailable, while Preferences, the Asset Manager, and the install ping all work. (Developer: `release.yml`'s stage step copies the loader the SDK installer places in the runner's `System32` — version-matched to the SDK the app was built against — plus its license into `licenses\`, and fails if either is missing; `packaging/licenses/` holds the license text. Verified by launching the packaged app with every Vulkan driver disabled: it starts, degrades, and pings.)
### Changed
* The install ping routes through the system proxy settings explicitly (`QNetworkProxyFactory::setUseSystemConfiguration(true)` before its first request). Official Qt builds already behave this way by default; the call pins it for a differently-configured Qt.

## [0.3.12] - 2026-09-09
### Added
* **An anonymous install ping, so we can see how many people run PoseStudio and which versions.** Each time it starts, the app sends one small signed request to posestudio.io carrying a random install ID, the app version, the operating system and CPU type, whether it was installed or runs portable, the Qt version it was built with, and the time of the ping — nothing else: no names, no files, no usage data. It fires a few seconds after launch, never delays anything, and ignores failures. Switch it off in Edit → Preferences → **General**, where the exact contents and your install ID are shown. (Developer: `src/core/installping.*`; the request is HMAC-signed with a key that only official release builds carry — passed from the `POSESTUDIO_PING_KEY` repository secret — so local builds and forks never ping; `POSESTUDIO_NO_PING=1` disables it for a run, and `POSESTUDIO_PING_URL` overrides the endpoint. The server side — the PHP handler, its MySQL schema, a signed test-ping script, and the stats queries — lives in `server/ping/`.)
### Changed
* **A full codebase refactoring pass — same app, cleaner inside.** Every oversized source file was split into focused modules along the boundaries the design already described, dead code was removed, hot paths were tightened, and every file now opens with a banner explaining what it is for. Nothing should look or feel different, with these deliberate exceptions: asset thumbnails are rendered on a square canvas at your display's pixel ratio (they were being drawn on a taller canvas, then downscaled and resampled into the icon slot — slightly blurred and offset); symlinked/junction subfolders are now excluded from the Asset Manager everywhere (they were shown in the tree but never in the grid, search, or the folder-has-assets icons — the recursive scans have no cycle protection, so consistent exclusion is the safe rule); arrow keys in the asset tree now populate the grid like a click; folder and collection "has assets" icons appear a moment after their placeholder instead of stalling the UI while big folders are scanned; the empty "Properties" side tab is gone (the Environment tab is the properties panel); File → Load Pose is an undoable edit and refuses to run mid-drag; Save/Load Pose remember their last folder; the View picker's dropdown shows a check mark on the current view; an orthographic side view of an EMPTY scene now shows the floor line; with a plain model (not a figure) selected next to a figure, the pose utilities, Ground, pins and pose save/load are greyed instead of silently acting on the figure behind the selection (the skeleton overlay still follows the figure); Preferences → General shows "not created yet" for the install ID until a ping has actually been sent (opening the page no longer creates one); the disclosure copy lists every field the ping sends (install-vs-portable, Qt version and timestamp were sent but not listed). (Developer: the module map — Asset Manager `src/assets/` in thirteen files (`assetnodeids.h`, `assetscan`, `assetdb`, the proxy model, tree view, two delegates, tooltip, `assetthumbnailloader` with QtConcurrent decode, `assetgriddragcontroller`, `assetbreadcrumblabel`, `assetmanagerwidget_menus.cpp`); `VulkanWindow` as one class across seven TUs (`_environment`, `_input`, `_camera`, `_ik`, `_pose`, `_bench`) with `ViewportStrip`/`AxisRotateBadge`/`viewpreset.h`/`ikdiagnostics.h` split out and `VulkanRenderer::scene()` replacing forty forwarders; the scene in `model`, `scenepipelines`, `sceneposing`, `cameraubo`, `shadowpass`, `outlinepass`, `lineoverlay`, `bonepicker`, `posefile`, `correctiveset`, `groundsampler`, `textureuploadcache`, `ray.h`; the rendering helper layer `vulkanhandles.h` (RAII owners for every raw device handle), `descriptorutil.h`, `attachmentimage`, `renderpassbuilder`, `samplercache` (shared samplers), `shaderlibrary`, `ibldata.h`, shared GLSL in `shaders/include/`, `parallelfor.h` in `viewport/util/`, and a swapchain pass that is single-sample colour only (the full-resolution 4× colour+depth targets it cleared and resolved every frame did nothing since the HDR/post rework); the figure importer in `figureutils`, `correctivescan`, `bonefixups`, `scenematerials`, `followeraddons` with a sparse corrective delta carry (bit-identical, verified by checksum on three figures; import parse time down about a third), a two-pass resolver that never pays a case-tolerant directory walk for a second root, cached documents reused by the corrective scan, and followers skipping the corrective machinery they discard; the IK rig in `ikrig`/`ikrigdrag`/`ikrigsolve`/`ikrigstepping` and the armature's IK in `armatureik`/`armatureikextract`/`armatureikpins`, the harness in five TUs; core conventions `appDatabase()`, the `AssetLibraries` repository (the one reader/writer of that table), `PreferencesManager::rememberedDirectory`, `AppTheme::install`, `HdriSelector`, `PlaceholderPreferencesPanel`, `MenuPickerButton`, the environment panel's dial table; `Constants::APP_VERSION` stamped from CMake's `project(VERSION)`; `.gitattributes`; only tagged release builds carry the install-ping key so pipeline-test artifacts never count as installs. The IK harness is bit-identical to before on all 29 phases except one gate that previously measured an unwritten field and now measures the real idle tremble.)
### Fixed
* **Asset Manager:** a right-click during a thumbnail drag left the drag stuck — the floating ghost stayed on screen for the session and no cell would hover-highlight; deleting an empty collection while a folder was displayed blanked that folder's view; a drag between collections could delete the asset from BOTH on a database error; a collection could be renamed to an empty name; a search with no matches lit the Search Results root as if it had results; a collection named with " / " was painted like a search path; thumbnails were blurred by a mismatched canvas (see Changed).
* **Viewport and posing:** an import landing while a released drag was still settling could push an undo entry against the wrong figure; a mouse press, undo/redo, delete or import during an X/Y/Z hold mis-bracketed the undo stack (the hold's edit could be lost, or a bogus entry pushed); a drag whose release was swallowed left the next empty-space drag rotating the joint instead of orbiting; undoing during the Ground button's free fall dropped the remaining fall onto whichever figure undo activated; a malformed `.pose` file was half-applied; two of three device-loss paths left the drag state and axis badge armed; a corrupt HDRI whose bake threw took the app down instead of logging; a remembered HDRI that no longer exists no longer pre-empts the default; the viewport strip could touch a freed badge at shutdown; transparent shells were sorted only within one model and by bind-pose position, so a translucent prop in front of a figure, or a figure lying down, blended in the wrong order; the wire-only shade modes showed an empty viewport on a GPU without wireframe support (now a Clay surface); the Vulkan handles created before a failing constructor step leaked; the HDR pass's depth attachment lacked a write-after-write dependency between frames in flight; `independentBlend` was assumed without checking; `compositeAlpha` was hard-coded; normal maps on back-facing fragments were mirrored.
* **Lighting panel:** an interrupted dial scrub (a popup grab or alt-tab mid-drag) left the undo bracket open and silently disabled lighting undo for the rest of the session; the HDRI button could name a different panorama than the viewport rendered when the developer override file was present.
* **Install ping:** the ping object was parented to the application (destroyed after the event dispatcher); a pipeline-test build carried the signing key and counted as a real install.
* **Figure import:** one malformed third-party corrective or addon file aborted the whole import; seam UV overrides drifted past a skipped polygon; a follower's base-vertex offset was the highest referenced index rather than the cage size (a corrective could alias into the follower); same-file `#id` gate URLs silently switched correctives off; far-parked UVs overflowed 32-bit integers in the gutter fill and the subdivision key; `.DSF` (upper-case) pack files were skipped; the inflate buffer leaked on allocation failure.
* **Full-body IK:** an eye or face-bone grab promoted to the head was classified as a limb drag (knee fold-plane freedom off) while a head-joint grab was a trunk drag; the harness's wheel-depth tremble gate measured a field nothing wrote (it passed forever); a debug block in the solver referenced a variable out of scope.

## [0.3.11] - 2026-09-09
### Added
* **Reset and mirror the pose.** Edit → **Reset Selected Joint**, **Reset Limb** (the joint and everything below it), and **Reset Pose** return joints to their rest position. **Mirror Pose** swaps the left and right sides of the whole pose, so a pose built on one side becomes its mirror image, and **Mirror Limb to Other Side** copies the selected arm or leg, mirrored, onto the other side (from the chest it mirrors both arms and the head). Right-clicking a joint offers Reset Joint, Reset Limb, and Mirror Limb too. Each is a single undo step; pinned joints keep their pins.
* **Scroll to push or pull a joint while you drag it.** A posing drag moves the grabbed joint in the plane facing the camera, so bringing a hand toward you or pushing it back used to take a release, an orbit, and a second drag. Now the mouse wheel during the drag moves the joint along the view direction — scroll up pushes it away from the camera, scroll down pulls it closer — while it stays under the pointer, in steps that scale with how close the camera is (about 5 cm per notch when framing the whole figure, millimetres in a close-up). The body follows through the same full-body IK as any drag. Holding X, Y, or Z still turns the wheel into that joint's rotation dial.

* **IK harness and bench grow with the features** (developer): the harness gains the "wheel depth steps" and "pose utilities: mirror + reset" phases (29 phases; the mirror is checked geometrically — the mirrored hand and foot must land on the reflection of the originals), and `POSESTUDIO_IK_BENCH=<bone>:depth` runs the scripted drag with wheel notches through the real camera path. The real-figure gates are calibrated against the base Genesis 8 Female skeleton dump; a morphed character's dump fails three stepping/crouch phases on unchanged code — a recorded robustness gap for a future round, not a regression signal.

### Fixed
* **The figure no longer deforms while you drag it.** The joint-driven corrective morphs (the sculpted fixes for bent elbows, knees, shoulders, and hips) used to be applied only when the mouse button was released: the body visibly crumpled at every deep bend during a drag, then snapped into shape on mouse-up. They now blend on the GPU every frame — the corrective weights are re-evaluated from the live pose each frame and the vertex shaders sum the deltas before skinning — so the figure stays correctly shaped throughout a drag, a gizmo or wheel rotate, an IK settle, and a pose load. The shadow and the selection outline follow the corrected surface too. (Developer: `Vertex::correctiveRange` + set 2 bindings 1/2; the CPU re-morph and its device-idle vertex-buffer re-upload are gone.)

## [0.3.10] - 2026-09-07
### Added
* **The full-body-IK harness is back, in the repo** (developer): `tools/ikharness/` builds as `PoseStudioIkHarness` (Qt-free, Vulkan-free, registered with CTest) and runs the IK math/constraint unit tests plus a drag-loop simulator over the *real* engine loop — the skeleton, pose, pins, and IK were split out of `Model` into a Vulkan-free `Armature` so the harness drives the same code the viewport does, tick for tick; its bench-path phase reproduces the in-app `POSESTUDIO_IK_BENCH` numbers exactly. Twenty-three real-figure phases (gentle pulls, arm raises, suspension, crouches, hover healing, strained releases, foot lifts, walks, stepping, pins, trembling, eye and finger grabs, a slouch, a child-scale figure) gate the behaviours the earlier rounds fixed. The real figure's skeleton comes from a dump the app writes with `POSESTUDIO_DUMP_SKELETON=<path>`; it is vendor rig data and stays out of the repo. `POSESTUDIO_IK_TRACE=1` now also reports, per tick, the worst planted-foot error at solve entry, in the solver's output, and in the applied pose.
* **Hold X, Y, or Z and roll the wheel to rotate a joint.** With a joint selected, holding one of the axis keys turns the mouse wheel into a rotation dial for that joint's channel (5° per notch, anatomical limits respected); a badge with the axis letter appears under the viewport strip for as long as the key is held. Each hold is one undo step, and the pose correctives settle when you let go.
* **The body part you grab lights up.** Selecting or dragging a joint tints the flesh that joint drives — the whole segment, twist bone included, fading out where the skin blends into the neighbouring bones — in the selection blue, so it's always clear which part you're pulling on or rotating, with no bones on screen. Only the selected part is tinted; clicking empty space clears it. Clicking a body part now grabs it anywhere along its length, too: a click on the middle of a thigh selects the thigh, where before it had to land near the hip or knee joint.
* **A view picker in the viewport strip.** Next to the shader picker, a dropdown lists Home View, then Top / Bottom, Front / Back, and Left / Right Views, and its label always shows the view the camera is in — "Perspective View" once you orbit away from a named view — so the keys, the View menu, and the picker agree.
* **Blender-style view hotkeys.** **1** / **3** / **7** snap to the front / right / top view, **Ctrl** + the same key gives the back / left / bottom view, **9** flips to the opposite side (180° about the up axis), **5** returns to the Home view (the same as the viewport's Home button), and **.** frames the selected object (everything, when nothing is selected). The keys work app-wide, whichever panel has focus (text fields still get their digits), on the number row and on the numpad with NumLock on or off; all eight are in the View menu too. The six axis views are **orthographic** — a true elevation or plan drawing with no vanishing lines, the floor a single line in the side views, as in a DCC's fixed side cameras — and any orbit drag returns to perspective.
* **Delete removes the selected object.** With an object selected in the viewport, the Delete key (or Backspace, the key labelled Delete on Mac keyboards) removes it, and Edit → Delete Selected Object does the same from the menu. The key is the viewport's own, so it never steals Delete from the Asset Manager.
* **Nine new shade modes.** Four wireframes — **Wireframe** (every edge, see-through), **Hidden Line Wireframe** (only the edges facing you, the surface blank), **Clay Shaded Wireframe** and **Texture Shaded Wireframe** (edges over the shaded surface), all following a posed figure's skinning — plus **Matcap** (the studio material sphere), **Ambient Occlusion** (the baked occlusion as grey), **Roughness Map** (the material's roughness as grey: white is matte, black is mirror-smooth), **Specular Only** (the PBR mode's specular reflection alone — highlight breadth shows the roughness map, highlight strength the specular weight and mask — with nothing else drawn, so a wet-plastic skin bug is obvious at a glance), and **Silhouette** (one flat light fill, for checking a pose's readability).
* **The selected object is outlined.** The figure or model you're working on now wears a crisp blue silhouette outline in the viewport — the app's accent blue, the same one the panels use for hover and selection — so it's always clear which object is selected, the way Blender outlines its active object. A freshly imported object is selected; clicking a figure's joint selects that figure; a plain click on any object selects it (a click on empty space clears the selection, and with it the joint gizmo); orbiting the camera never changes the selection. The outline is anti-aliased, keeps its exact colour whatever the exposure and tonemap dials do, and traces the object's whole posed silhouette even where another object is in front of it.

### Changed
* **A sustained sideways lean steps sooner.** With the feet held on the floor, a hard lateral chest drag leaned the hip 19cm on planted feet without ever stepping; the balance-effort threshold that triggers a re-planting step is lowered so the figure steps to follow the lean again (three steps on a 45cm chest drag, the chest ending 13cm from the cursor instead of 22cm). Walks, crouches, and pinned-joint drags are unchanged.
* **Grab and drag to pose — no modifier key.** A plain left-drag on any joint now moves it with full-body IK, the gesture that used to need Ctrl; **Ctrl+drag** now rotates just that one joint (the former plain-drag free rotate). The rotate-gizmo rings around the selected joint and the balance support polygon drawn on the floor during a drag are gone — the selection outline, the optional skeleton overlay, and the pin markers are the only overlays now.
* **The shader picker is regrouped and renamed.** Its rows now sit in four separated groups by what you want to see: lit shading of the real materials (PBR Shaded, Texture Shaded, Flat Texture Shaded, Cartoon Shaded), untextured form studies (Matcap, Clay Shaded, Lighting Only, Silhouette), the wireframes, and the data views (Albedo, Ambient Occlusion, Roughness Map, Specular Only, Normals, UV Checker). The skin and metal matcaps are no longer listed (their shading code remains and can be re-added as rows).
* **Separator lines are more visible.** Menu separators — the File/Edit/View menus, context menus, the shader picker — and the Asset Manager's section and search dividers are drawn in a lighter grey that actually reads against the dark surfaces.

### Fixed
* **Crouches no longer sink the feet through the floor.** Dragging the hip down (or pushing the chest down) used to bury a planted foot up to 4-6cm below the floor and slide it several centimetres while the gesture was in progress, with the release settle pulling it back: the solver kept the feet on their pins, but the damped per-tick blend of the pose lowered the hip faster than it folded the knees. Each drag tick now lifts a sunk foot back to the floor through its own leg — vertically only, so the lateral slip that tells the figure to step is untouched. A 12cm hip crouch's foot sink drops from 4.6cm to 2mm and its mid-gesture slide from 7.6cm to 2.4cm. (The toe joints can still dip about a centimetre through the floor at the deepest point of a crouch, as the sole pitches slightly.)

## [0.3.8] - 2026-09-04
### Added
* **IK benchmark and timing diagnostics** (developer): `POSESTUDIO_IK_BENCH=<bone>` runs a scripted drag of that joint with no desktop input and prints per-phase tick/frame intervals and hand-to-cursor lag; `POSESTUDIO_IK_PERF=1` prints the same report once per second during a real drag.
* **Joint limits and balance are visible.** Each rotate-gizmo ring now shows its channel's allowed sweep as the bright arc, dims the forbidden part, greys out locked channels, and marks the current angle with a tick. During a full-body IK drag the balance support polygon is drawn on the floor between the planted feet.
* **Joint pins are part of the pose.** A pinned joint now rides in the pose snapshot: pinning and unpinning are undoable edits, undoing a drag restores the pins of that moment, and `.pose` files save and restore their pins (as `@pin:` rows, which older files and builds simply ignore; a file without pin rows loads with none).
* **View → Show Skeleton.** A checkable menu action — mirrored by a bone-icon button in the viewport's top-right strip — toggles the joint→parent skeleton overlay over a posed figure. Off by default, so the rotate gizmo stays the only posing affordance; joints remain clickable either way. (#28 — thanks @DmitryAkDev)

### Changed
* **Walking the figure by the hip plants its feet where they belong.** Each step used to land a few centimetres inside the stance with the leading foot sinking through the floor, because the solver's leg seed could leave the knee stuck on the side it cannot bend to. The knee now always seeds on its flexion side, and a hip-drag step re-creates the stance the figure held under its hip at the start of the drag; a 60cm walk lands both feet exactly on their stance spots at floor height.
* **No joint goes through the floor.** The full-body IK solver now treats the floor as a hard constraint on every free joint (each keeps its rest clearance, ground contacts their rest height), and the cursor cannot ask the grabbed joint for a spot below its clearance.
* **The Ground button lets the figure fall.** Instead of jumping to the floor, a hovering figure now drops in free fall, 9.81 m/s² from rest on real time, so a metre of height lands in about half a second, and stops exactly on the ground. A figure sunk below the floor is still lifted out in one step.
* **The grabbed joint now sticks to the cursor.** The joint you drag is closed onto the cursor exactly every tick through its own limb — the same joint-space fit that holds pinned joints — while the rest of the body keeps its damped, balanced follow-through underneath. Hand lag at a moderate drag speed is halved (about 1cm, from 2cm), a fast flick's lag drops four-fold, the hand no longer rests short of the cursor when it stops, and idle-joint trembling during a slow pull is gone entirely. The cursor filter opens fully while moving, since the fit no longer amplifies pointer noise.
* **IK drags reach where you point — the elbow's fold plane now turns.** The solver carried no twist at all, so an arm could only fold in the plane its drag-start pose left it in: a hand pulled in front of the chest stopped up to 10cm short of a plainly reachable point and sat there, which read as lag. Elbows now bend in any plane the upper arm's authored twist range allows, the pose extraction realizes that twist exactly, a finger grab keeps tracking the finger as the hand turns, and the grabbed joint's own motion is speed-shaped. Measured on the real figure: the resting miss after a fast flick 103mm → 33mm, an overhead reach 11cm higher, and idle-joint trembling during slow pulls down 4-18×.
* **Pulling the head up straightens the back.** A head or chest pulled upward used to move only the neck, because the rule that keeps an arm raise from bending the spine excluded the whole trunk. Trunk gestures now keep the spine in the solve: a slouched figure straightens as its head is lifted.
* **Crouches keep both feet on the floor.** Pushing the chest down or dragging the hip into a squat used to bury one foot up to the ankle, because a knee could only fold in the plane it started in while the pelvis dropped and rolled. Knees now turn their fold plane through the thigh's authored twist range during crouches, walks, and foot drags, so the feet stay planted; the child-scale crouch's foot drift dropped from 5cm to a millimetre.
* **Releasing a chest or hip drag now lands the figure on its feet.** After a big lateral chest drag with steps, or a pull beyond the arm's reach, the figure used to be left standing a few centimetres in the air: the release settle was holding the let-go joint fixed even when it was the trunk, and a foot that stepped beyond its leg's reach had locked the pelvis in place. Trunk gestures now let the body drop onto the planted feet, and a foot can never claim more reach than its leg has.
* **Releasing an IK drag lands the figure exactly.** The animated release settle now finishes with every planted foot exactly on its ground contact — position and flat sole — and the released joint exactly where it was let go, instead of within a 5mm band: a moderate strained pull's release lands its feet within a third of a millimetre (was 5mm). Drag motion itself is unchanged — holding the feet exact mid-drag was measured to mask the balance stepper's strain signal and was rejected.

### Fixed
* **A second figure in the scene can be posed.** Every posing action used to address the first figure loaded; clicking a joint on any figure now makes that figure the posing target, and undo follows the figure each edit belonged to.
* **Delete is back on the context menu after a walk or crouch.** Right-click picked the model by its rest-pose bounds, which a full-body IK walk had left behind; a posed figure is now picked by where its joints actually are.
* **Grabbing the head no longer makes it tremble.** Clicking a head picks one of its face joints, and the drag target for such a grab was following the head's rotation; the neck turns the head with every move, so the target chased its own motion and the head shook. A head grab now keeps a fixed grab offset (the rotating offset stays for finger grabs on a hand, where it is needed).
* **Linux build with GCC/clang.** `FabrikSolver::Settings` — a nested struct with default member initializers — was used as a `= {}` default argument inside its enclosing class, which GCC and clang reject (GCC bug 88165); MSVC accepts it, so the break only showed on Linux. The settings struct now lives at namespace scope with an in-class alias, so every call site is unchanged. (#24 — thanks @DmitryAkDev)
* **Linux: the viewport control strip and the boot splash appeared as a second window, stacked behind the main window.** Both overlays are owned top-level windows (the native Vulkan viewport composites over ordinary child widgets) but were created with the full application-window type, which X11/Wayland window managers list in the taskbar and stack as they please. They are now tool windows — kept out of the window list and above their owner on every platform — and the strip re-asserts itself whenever the main window is activated. (#25 — thanks @DmitryAkDev)
* **Fresh installs since 0.3.6 were missing the `Preferences` table** ("no such table: Preferences" at startup). The schema file is executed by a split-on-semicolon loader, and a header comment added in 0.3.6 contained a semicolon that corrupted the first statement. The comment is reworded, and a startup repair recreates the table on already-affected databases — no Factory Reset needed. (#26 — thanks @DmitryAkDev)
* **Figure import on Linux/macOS: mixed-case content paths now resolve.** Figure files reference content with different letter case than the folders on disk, which NTFS absorbs but case-sensitive filesystems reject — so every import there failed with "cannot resolve base geometry". The resolver now tries the exact-case path first and falls back to a per-component case-insensitive match. (#27 — thanks @DmitryAkDev)

## [0.3.7] - 2026-08-31
### Added
* **Full-body IK posing — Ctrl+drag any joint and the whole body follows.** The figure is anchored at its **ground contacts**, not its hip: planted feet stay planted (each carrying a reach leash, so no pull can hoist the body off them), the pelvis floats and **auto-balances** (center of mass against the feet's support polygon), and the grabbed joint tracks the cursor in a camera-parallel plane. Gestures behave like human ones: grabbing a finger drives the whole arm (clicking near a hand almost always picks a finger); pulling a hand up raises the arm along its natural arc against a stable posture; pushing the chest — or dragging the hip — down folds a crouch over weight-bearing flat soles; a sustained pull beyond reach **lifts the figure off the ground** to dangle from the grab point, limbs hanging under gravity within their joint limits; and releasing the mouse settles the body onto its feet as a short animation, with the posed joint staying exactly where it was let go. A slightly-hovering figure is healed back onto the floor by its next drag. Everything integrates with the existing posing stack: the anatomical joint limits remain authoritative, correctives fire on release, poses round-trip through save/load (now including the root's translation, which older files and builds simply ignore), and each gesture is one undo entry.
* **The figure steps to stay balanced — and walks.** When a sustained drag carries the upper body beyond what leaning can absorb (or a foot is being dragged off its plant), the figure re-plants a foot at its **balanced stance** — the original stance shape centered on where the body is going — with an animated step; alternate feet leapfrog naturally and never cross. Dragging the **hip** sideways walks the figure: steps aim at where you're taking it, and the walk ends standing in the original stance centered exactly where the hip stopped, a final gathering step bringing the trailing foot home.
* **Motion engineered to feel natural, not mechanical.** The drag runs as a damped 60 Hz process with velocity shaping — gestures accelerate like a real limb spinning up and brake smoothly into their target instead of moving at a constant rate and stopping flat — plus an adaptive cursor filter (heavy smoothing while you hold precisely, tight tracking on a fast flick), per-joint anti-shimmer damping, and a true settle-freeze, so a held pose is rock-still.

### Changed
* **Dual-quaternion skinning replaces linear blend skinning** — the skinning model the figure format actually authors its weights and pose correctives against. Deep bends keep their volume: a fully flexed knee holds its shape instead of collapsing into a pinched fold.
* **Deep-bend correctives now fire on every supported figure generation.** Four compounding causes fixed: point-release generations whose own content ships no corrective packs inherit the previous generation's (matched structurally — an identical base cage — never by product name); only formulas driving the corrective's *own* value contribute (vendor character files bundle dozens of unrelated bone-adjustment formulas in the same modifier); percent-encoded gate references are decoded before matching; and the authored channel min/max is enforced — an *extension* corrective driven to −14 at full knee *flexion* was cratering every deeply bent thigh.
* **The key-light shadow follows the pose.** The shadow frustum now fits the **posed** figure (bind bounds unioned with the posed joints), so a leaning head or outstretched arm no longer slips past the map's edge as transient dark bands while posing.

### Fixed
* **Momentary "exploded geometry" streaks while posing.** Joint matrices were uploaded into a single GPU buffer that a still-executing frame could be reading — at 60 Hz posing, vertices skinned by half-updated matrices tore into spikes for a frame (and corrupted that frame's shadow). Joint buffers are now per frame in flight.
* **A full-system IK review (eight independent review passes plus a manual one, every fix verified in the drag-loop simulation harness) hardened the seams:** the Ground button and IK now agree on where the floor is (IK used to heal feet back to the floor the button had just moved them from); **small figures work** — every geometric threshold scales with the figure's size, so a child-scale character crouches and walks instead of losing its footing to adult-sized tuning; Ctrl+*click* is a pure selection (it used to visibly nudge a hovering figure and commit an undo entry for a click); the motion dynamics are independent of the mouse's polling rate; a drag whose mouse-up was swallowed by a dialog no longer wedges the input state; deleting a figure mid-drag, saving a pose mid-settle, and losing the graphics device mid-drag all resolve cleanly; and pose-file translation rows are validated on load (a corrupt row could tear the skeleton or feed NaN into the skinning).

## [0.3.6] - 2026-08-19
### Fixed
* **A corrupt or malformed figure file can no longer crash the app.** The figure importer's parsers (geometry, UVs, morph drivers, grafts) validated everywhere except a handful of spots that trusted file data — including one path where an out-of-range vertex index corrupted memory instead of failing. All of them now reject bad data cleanly, the OBJ importer bounds-checks face indices the same way (and handles files that mix faces with and without normals), and a gzip-corrupt figure file now names *which* of the hundreds of files it touched was bad.
* **Characters with multi-level morph-driver chains resolve their full shape.** The morph resolver evaluated each driver channel exactly once in discovery order, so a control driven along two paths could bake a partial value into every downstream morph. Driver graphs are now evaluated to a fixed point, so deep control → head/body → component-morph chains land at their exact dialed result.
* **Follower-addon robustness.** An addon skeleton listing a child bone before its parent no longer silently reparents it to the figure root; an addon materials preset's *relative* texture references now resolve against the preset's own folder; and both graft-declaration forms are tolerated.
* **Importing from folders with non-ASCII characters (é, ü, CJK) now works on Windows.** The process runs with a UTF-8 code page (plus a UTF-8-aware HDR loader), so OBJ/figure/HDRI files in such paths no longer fail to open on systems whose legacy ANSI code page differs.
* **A lost graphics device no longer aborts the whole application.** Runtime Vulkan failures (driver reset/TDR, a failed environment upload) are now caught at the window boundary: the viewport disables itself and reports the error instead of terminating PoseStudio — and a failure mid-frame can no longer deadlock the render loop. Also fixed: resizing the window in a stylized (non-PBR) shade mode sampled a never-rendered bloom target (a Vulkan validation violation), minimizing at just the wrong moment could rebuild the swapchain at 0×0, a model whose meshes were all empty bound a null descriptor set, and mapped GPU uploads now explicitly require coherent memory instead of assuming it.
* **Asset Manager correctness sweep.** Breadcrumb links no longer break on paths containing an apostrophe; libraries registered at a drive root (e.g. `D:/`) get working breadcrumbs, "Find In Library", and a visible name; folders can no longer get permanently stuck with the placeholder "hit" icon after a refresh; a right-click during an active drag no longer commits the drop; thumbnails can no longer land on the wrong items after drag-reordering while they load; collections sort case-insensitively everywhere (matching the tree's other sorts); moving an asset onto the Collections header can no longer lose the asset when collection creation fails; and a stale tooltip no longer survives the grid being rebuilt.
* **Factory Reset is dependable.** If the database file can't be deleted (e.g. held open by another process), the reset now wipes every table in place instead of silently keeping all data while claiming success — and the automatic relaunch starts clean instead of replaying the original command line (which could re-import the last session's file).
* **Cutout masks whose resolution differs from the diffuse map bake correctly** (a Qt format conversion corrupted the alpha bake for mismatched sizes — visible on lash/brow cards with non-matching mask sizes).
* **Smaller fixes.** Adding an asset folder that's already registered now says so instead of silently doing nothing; the initial window size is clamped to the screen on portrait/4:3 displays; disabled icons render sharp at high-DPI scaling; the Dome backdrop no longer smears when the camera dollies outside the dome radius; the Dome menu tooltip actually appears; and two shader edge cases that could spread NaN pixels through the blur passes are guarded.

### Changed
* **Performance touches across the board.** Plain mouse hover no longer redraws the whole scene; the HDRI menu caches its thumbnails between opens (rebuilds only what changed on disk); the key-light shadow lookup is skipped entirely when the shadow dial is at 0; figure import wastes less time and memory (single ground-sample allocation, the ambient-occlusion bake checks its size cap before materializing 1.8 GB of triangles, nearest-vertex searches scan only new cells, and the texture seam fill stops spawning threads for tiny pyramid levels).
* **Repository refactor for open source.** A full review-and-cleanup pass over every subsystem: dead code and unused schema removed (including five never-used database tables — one with a plaintext-password column design — and dead stylesheet rules), stale comments corrected across the codebase, contributor docs brought up to date (CONTRIBUTING's development setup, SECURITY's actual scope, GOOD_FIRST_ISSUES rewritten against the current code), the README gained a "What Works Today" section and live sponsor links, the missing `ATTRIBUTIONS.md` (Lucide icon license) now exists, `.gitignore` no longer hides Wavefront `.obj` assets, and this changelog's `[0.3.3]` entry was repaired (a merge had left an entire release's notes headerless inside it).

## [0.3.5] - 2026-08-18
### Added
* **Character imports are ~4–5× faster.** The texture pipeline decodes each unique map file exactly **once** — figure zones share atlas files, and the old path re-decoded and re-uploaded the same 4K image per zone — with decodes running across all cores and one GPU upload per unique image (a large VRAM saving too). Textures are decoded at a 4096 cap (8K bump/roughness maps cost 4× everything for detail the viewport can't resolve; JPEGs even decode directly at the reduced size). Corrective and morph files load in parallel with a cheap pre-filter that skips full JSON parsing of the hundreds of plain shape morphs that can never be correctives. A reference character that took 17 s now imports in about 3.5 s — comfortably faster than the leading desktop app on the same machine.
* **Real soft ground shadows (PCSS).** The floor shadow is now a percentage-closer soft shadow with contact hardening: dark and crisp where the feet touch, widening, lightening, and dissolving as it trails away — like a real area-light shadow. The key light **auto-aims at the HDRI's dominant light** when an environment is picked (so the shadow always falls away from where the light visibly comes from), and in the PBR mode it follows the Rotation dial, so spinning the environment swings the highlight and shadow with the visible backdrop.
* **Shadow controls.** A new **Shadow** group in the Environment tab: enable (off skips the shadow pass entirely), intensity (figure self-shadowing and ground shadow alike), softness, and reach — all live, undoable, with restore buttons.
* **Ground button.** A new viewport button beside Home drops the figure so its *current pose's* lowest point rests exactly on the floor — a knee bend lifts the feet off the ground; this puts them back.
* **Debug builds label themselves.** The window title of an unoptimized build reads "[Debug build — slow imports]", so a slow session can never be mistaken for a real performance regression again.

### Changed
* **Skin reads as skin from every angle — the wet-plastic look is gone.** Several compounding causes, each fixed at the root: the screen-space subsurface blur no longer smears **specular** (surface reflection now renders to its own target and is composited back crisp — smeared glints were the "wet film" no material tuning could dry); materials' authored **detail-map strengths** are honoured (a skin dialing Normal Map 2.5 rendered at 1×, leaving the surface so coherent the sheen read as gloss); the environment specular gained **specular anti-aliasing**, the Frostbite dominant-direction correction, and a decisive roughness-keyed energy fade (the milky veil pinned to the roughness map's blotches); and the 2017-era "top coat as the main specular" material style is translated honestly (coat colour folded into its weight) instead of as a full-white glaze.
* **Bump maps render pore-scale grain only.** The bump gradient is high-pass filtered, so a bump map's broad vein/stretch content can never print as visible lines at any authored strength.
* **New default look.** Stock environment `Studio Small 09`, exposure 0.65, rotation 0°, key azimuth 45°/elevation 20°, shadow intensity 0.75 / softness 0.25 / reach 4.

### Fixed
* **"Stretch-mark" streaks down every figure's legs** — self-shadowing acne from the key light at grazing angles, eliminated with normal-offset shadow sampling (robust at any light elevation).
* Import no longer stalls for seconds on fibermesh brows or tiled lash strips during the texture seam fill (triangle dedup + a scanline coverage raster).

## [0.3.4] - 2026-08-17
### Added
* **Real-time shadows.** The key light now casts real shadows: a per-frame depth-only shadow map (2048², hardware PCF) gives the figure self-shadowing — under the chin and nose, arm on torso — and its ortho frustum auto-fits the scene *and* the shadow's landing spot on the floor, following the Key Light azimuth/elevation dials live. The floor grid composites a soft **ground/contact shadow** under the figure, which is what finally grounds it on the plane instead of floating.
* **Visible HDRI backdrop with a new Backdrop panel group.** The environment that lights the figure can now be drawn behind it. A new **Backdrop** group in the Environment tab controls it: **Mode** (Off — the default, keeping the clean viewport grey while the HDRI still lights the figure; Environment — the panorama at infinity; **Dome** — ground projection, where the panorama's floor lands on the viewport's ground plane so the figure stands *in* the environment), **Blur** (photographic background defocus), **Brightness** (backdrop-only exposure — "background a stop down" without touching the subject), and **Dome radius**. All live dials with defaults and restore buttons.
* **An HDR post-processing pipeline.** The scene now renders offscreen in linear HDR (RGBA16F, same MSAA) and finishes through a post chain: **screen-space subsurface scattering** (a masked, per-channel-width blur — red diffuses farthest, like real flesh — driven by each material's translucency, so skin softens while eyes, cloth, and the grid stay crisp), **bloom** (soft-knee bright extract + separable blur, so bright HDRI sources and catchlights glow), and a fullscreen **ACES composite** (tonemapping moved out of the material shader, so bloom sees true radiance; the stylized shade modes pass through untouched).
* **Baked ambient occlusion.** Every import bakes per-vertex AO (hemisphere rays against the model's own opaque geometry, parallel across cores) on the final subdivided mesh. Cavities — eye sockets, nostrils, under the jaw, between fingers — stop receiving full sky light, which removes the waxy look; transparent shells receive but never cast occlusion, so eyes stay bright. The key light relies on its real shadow map instead.
* **Much deeper skin materials.** The renderer now consumes the material data skin actually authors: **dual-lobe specular** rendered as two GGX lobes (broad sheen + tighter reflection), the **Top Coat** clear/oily layer, **translucency maps** scaling the subsurface response per region (ears and nose wrap more than bone-backed skin; cloth stops wrapping like skin), and **backlit transmission** — light through thin regions, so backlit ears glow warm red. The per-region **roughness, specular-mask, translucency, and micro-detail (pore) normal maps** are all sampled now instead of reduced to scalars, over import-baked **UV tangents** (with the screen-space fallback retained).
* **`.exr` environment support.** OpenEXR panoramas work everywhere `.hdr` does — the environments folder, its subfolders, the thumbnail menu, and the `<appDir>` override — decoded via tinyexr (whose ZIP inflate reuses the miniz already in the build; no new system dependency).
* **HDRI menu folder categories.** Panoramas can be organized into subfolders of the `hdri/` library folder; the thumbnail menu groups them under a heading per subfolder (bright title, spacing, and a hairline rule), with uncategorized files listed first. The startup default resolves wherever the stock panorama was filed.
* **Per-setting restore buttons.** Every Environment-tab dial — and the HDRI selector and Backdrop mode — has a small restore-default button on its right; the bottom button is now "Restore All Defaults".
* **Lighting edits are undoable.** Environment-panel changes join the same undo stack as pose edits (one entry per completed scrub/type-in/toggle, in chronological order with poses), and Edit → **Undo/Redo** are now real menu items with app-wide `Ctrl+Z`/`Ctrl+Y` shortcuts — working regardless of which panel has focus, while text fields keep their own undo.

### Changed
* **The wet-plastic skin fix.** Skin materials disable their glossy lobe and author the real response in dual-lobe specular — the importer used to read the disabled lobe's zero roughness, rendering skin mirror-smooth. Materials are now interpreted through their active specular **lobes** (dual-lobe → glossy → defaults), with reflectivity mapped to true F0 (skin lands at its real ~2–3%), map-carried channels handled honestly, a hard 4%-dielectric F0 cap, and a horizon fade that stops bump-bent normals reflecting environment light from under the surface. Eye corneas keep their mirror catchlights — that shine is authored, and real.
* **Cross-file material bases are resolved.** Newer-generation skin materials extend a base material in another file; its channel defaults (roughness, transparency and friends) are now merged instead of silently falling back to importer defaults.
* **Transparent surfaces draw in depth order.** The transparent pass sorts meshes back-to-front from the camera, so layered shells (lashes over cornea over sclera) blend correctly from any viewing angle.
* **New default look.** Defaults are retuned around the stock `Brown Photostudio 01` environment (matched by name, `.hdr` or `.exr`, wherever it's filed): exposure 0.75, diffuse 0.5, specular 1.0, ambient fill 0.15, key 1.25 at azimuth 0°/elevation 50°, rotation 30°, subsurface 0.5, rim 0.25.

### Known Issues
* The newest-generation *eyelash follower's* materials aren't resolved yet — on those characters the lash strips render as opaque grey geometry (previous-generation figures' integral lashes are unaffected).

## [0.3.3] - 2026-08-16
### Added
* **Follower addons — characters now load complete.** A character preset can declare *follower figures* to be loaded after it (a `scene_post_load_script` block): eyelashes, fibermesh eyebrows, and replacement anatomy such as a stylized character's cartoon eyes. The importer now parses those declarations, loads each follower through the same figure pipeline (they're self-describing wearable figures), applies its materials preset, and merges it into the character — skeletons merged by bone name so followers track the figure's pose. Fitting follows three data-driven rules learned from real content: ordinary followers are **shape-follow projected** onto the character's morphed surface (each vertex takes the morph delta of the nearest visible base-cage vertex — without this, eyebrows authored against the base figure float in front of a morphed forehead); followers declaring a *populated graft* are vendor-fitted in place and are left exactly where authored; and projection deltas are never sampled from surfaces the preset hides (stylized morphs stash their hidden stock geometry, which would otherwise throw followers across the face). Materials presets are applied in both their forms — ordinary scene-materials documents and the animation-track form (`preset_hierarchical_material`) the anime-eye products use. The visible results: standard characters gain their previously-missing eyelashes, an anime-style character imports with her cartoon eyes instead of empty eye sockets, and character-specific fibermesh eyebrows land on the character's actual brow ridge.
* **Opacity (cutout) mask support.** A material's opacity can be masked by an image (eyelash and eyebrow cards, older generations' eye shells) — those masks are now baked into the diffuse map's alpha channel at import and honoured by the shader, so lashes and brows render as real strand shapes instead of opaque cards, and masked meshes reach the transparent pass even at full scalar opacity. The bake runs before the seam gutter-fill, so masked textures get the same mip-bleed protection as colours.
* **Drag Number Box — the app's standard numeric input.** The Environment tab's slider + spin-box pairs are replaced by a single DCC-style scrub field (`src/widgets/dragnumberbox.*`, the first resident of a new shared-widgets module): a left-to-right range fill in the app's muted accent behind a centered value, press-and-drag to scrub (a full-width sweep covers the whole range; the left-right-arrow cursor on hover signals it), and a plain click to type the value directly (Enter commits, Esc cancels). The tab's checkbox also swaps its solid-fill checked state for an accent check glyph, and every hover accent in the tab now shares one colour.
* **Viewport Home button.** A new button beside the shade-mode picker returns the camera to the default perspective framing. The default framing values are now shared constants, so the startup view and the Home view can't drift apart.
* **New Environment-tab controls.** The Key Light group gained **Azimuth°/Elevation°** sliders (the key light is finally movable — it was hardcoded front-right; all analytic shade modes follow it), and a new **Skin & Rim** group holds **Subsurface** (the strength of the skin-translucency terminator) and **Rim light** (a photographic back light that lifts the figure's dark side off the background). All live shader dials — no re-bake — and covered by Reset to defaults.
* **Default user library ("My PoseStudio Library").** On first launch the app creates a "My PoseStudio Library" folder in the user's Documents and registers it as an ordinary asset library (fully user-manageable; an existing library by that name — wherever the user keeps it — is honoured instead, and a deliberate later removal isn't recreated). This is the user-facing home for personal content the app itself consumes, starting with HDRI environments.
* **HDRI thumbnail menu.** The Environment tab's HDRI selector is now a drop-down showing a large (178×89) image **thumbnail of each panorama** next to its name — a same-basename image file in the same folder (any common format; the stock previews ship as `.jpg`), matched the same way the Asset Manager pairs thumbnails. The list shows six environments at a time with a scroll bar for the rest (the current one highlighted and scrolled into view), rebuilds every time it opens so files added while the app runs appear immediately, and ends with a left-aligned "Open HDRI Folder…" link that jumps straight to the folder to drop new panoramas into. The tab's numeric spin buttons also gained **+/−** glyphs so the increment/decrement direction reads at a glance.

### Fixed
* **Some characters imported at up to three times their real size.** A control that scales a body *part* propagates through dozens of per-bone scale channels (e.g. a head-scale dial driving ~80 face-bone scales); the importer summed every one of those into the figure's overall scale. One teen character landed at 5.4 m tall. Only formulas targeting the figure's root node now set character height — verified: the teen character resolves her correct 0.91 scale, and a child figure from an older generation still resolves its legitimate 0.54.
* **Older-generation base figures rendered blank white eyeballs.** Their pre-physically-based materials express opacity through the format's core `transparency` channel ("Opacity Strength"), which the importer didn't read — so the eyes' clear cornea/moisture shells drew as opaque white balls over the irises. The channel (scalar and image mask alike) is now honoured, and those figures get correct eyes, strand-shaped lashes, and brows.
* **The "Exposure & Tone" section title rendered as "Exposure Tone"** with a stray underline (an unescaped ampersand read as a keyboard accelerator).

### Changed
* **Viewport overlay buttons keep the standard arrow cursor** (no more hand cursor on hover), matching platform conventions. The one deliberate exception is the new Drag Number Box, whose left-right-arrow hover cursor is the affordance that it scrubs.
* **PBR mode: more photoreal skin.** Two root causes of the "blown-out front, reddish dark back" look are fixed. The cheap subsurface term used to be an additive red band that saturated across the *entire* shadow hemisphere — the whole unlit side rendered dark red; it's replaced by a physically-grounded **per-channel wrapped Lambert** on the key light (red wraps farthest past the terminator, then green, then blue — energy-conserving), which produces the warm terminator of translucent skin and decays to neutral darkness in shadow. The front was double-lit by the analytic key stacked on an environment that already contains the sky's light — the key's default intensity is reduced (0.85) and the wrap's energy conservation relaxes the lit side further. The shadow side is lifted by a higher default ambient fill (0.16) and a new dialable photographic **rim light**, so the figure's dark side stays readable and separates from the background instead of crushing.
* **HDRI environments now live in the user's asset library** (`My PoseStudio Library/hdri`) instead of a read-only folder next to the executable — a folder the user is accustomed to browsing, where adding an environment is just dropping an `.hdr` file (plus an optional same-basename preview image for the menu thumbnail). The viewport's default environment and the Environment tab both read this folder; `<appDir>/environment.hdr` still works as an explicit override, and with no panoramas present the built-in procedural studio takes over. The `resources/hdri` folder and its build-time mirror step are gone — HDRIs are user content, not build output (packaging/installers are responsible for placing the stock set into the user library).
* **Stock HDRI previews converted `.webp` → `.jpg`** — Qt only decodes `.webp` when the optional "Qt Image Formats" add-on is installed, so the bundled previews now use a format every Qt build decodes. User-supplied `.webp` previews still work where that add-on is present.

## [0.3.2] - 2026-08-14
### Changed
* **The viewport renders on demand, not continuously.** The render loop no longer re-arms itself every frame — a frame is drawn only when something changed (camera input, posing, imports, lighting/shade-mode changes, resize). Previously the GPU redrew at full swap rate even when idle, and the vsynced present throttled the whole GUI thread, making the entire app feel sluggish; the viewport now idles at zero GPU cost. A follow-up frame is self-scheduled only when the swapchain was just rebuilt. Un-obscuring the window also no longer forces a needless swapchain rebuild (only a real size change does).
* **Image-based-lighting bakes are multi-threaded.** The GGX specular prefilter and the BRDF-LUT integration (millions of samples, previously single-threaded) now run across all CPU cores — removing the multi-second startup freeze on first viewport expose and making Environment-panel HDRI switches several times faster. (New shared helper: `rendering/parallelfor.h`, used by every CPU bake.)
* **Faster figure import.** The per-corrective Catmull-Clark delta-field subdivision (~100+ full-mesh stencil passes, the dominant slice of subdivision's import cost) is parallelized across cores, and the skin-weight blending in subdivision no longer allocates a hash map per cage face/edge (~50k calls per import). Texture decode also got cheaper (see the Asset Manager note — the same decode path serves imports).
* **Snappier Asset Manager.** Thumbnails are now decoded *at* thumbnail size (letting the JPEG codec do the reduction) instead of decoding full-size images on the GUI thread and scaling down — eliminating browse-jank in folders with large preview images. The directory tree also stops rebuilding its state icons from resources on every repaint, and posing no longer allocates per mouse-move in the skinning update.

### Fixed
* **White dots in the centers of the eyes.** Material *colours* dialed by a preset were ignored in favour of the channel defaults (`current_value` vs. `value`) — so characters that dial their pupil diffuse to black rendered a light-grey pupil disc that read as a bright white dot. Dialed colours are now honoured; as a side effect **all figure textures render at their true brightness** (they were previously multiplied by a 75%-grey default tint).
* **White seam lines along UV boundaries when zoomed out.** Character textures leave the space between UV islands white with no padding, so the GPU mip chain averaged that background through every texture seam at viewing distance (clean when zoomed in, worse zoomed out). Decoded textures are now gutter-filled at import: the mesh's own UV coverage is rasterized and the unused background flooded with colours dilated from the islands (a pull-push fill, applied to diffuse and normal/bump maps alike), so every mip averages island colour into island colour. Covered texels are untouched — close-up rendering is byte-identical.
* **The mid-forearm joint no longer bends.** The figure format marks unposeable rotation channels with a `locked` flag (distinct from `clamped` limits); the importer now honours it, pinning those axes at rest. This locks the anatomically impossible bend at the mid-limb twist joints — most visibly the mid-forearm joint on both arms — while keeping their natural axial twist free within its authored range. The old name-based twist-bone heuristic missed this joint (its name doesn't say "twist" in most figure generations) and is now only a fallback for old figures that predate the `locked` flag.
* **Posing-overlay flicker.** The skeleton/gizmo overlay's vertex buffer was rewritten by the CPU each frame while the previous in-flight frame could still be reading it on the GPU; it's now one buffer per frame-in-flight.

## [0.3.1] - 2026-08-12
### Added
* **Image-based lighting (IBL).** The viewport is now lit by a whole HDR *environment* rather than a hand-tuned light rig, giving soft wrap light, natural rim, environment colour bleed, and real glossy reflections that stay consistent as the camera orbits. It's a CPU-baked split-sum implementation: spherical-harmonic diffuse irradiance + a GGX-prefiltered specular cubemap + a BRDF LUT, all baked from the environment at load. Materials gained a metalness channel.

The app loads a bundled default (`hdri/Golden Gate Hills.hdr`); drop an `environment.hdr` next to the executable to override it with any HDRI. A procedural neutral-studio environment is the built-in fallback when no `.hdr` is present. (`stb_image` is now a fetched build dependency, used only to decode `.hdr` in the app layer so the render core stays codec-free.)
* **Environment properties tab.** A new tab in the right-hand docker with live controls for the viewport lighting: HDRI selection (auto-populated from the bundled library), environment rotation, exposure, ACES tonemap toggle, image-based diffuse/specular levels, an ambient fill, and key-light intensity — plus a reset-to-defaults. Every control except the HDRI switch is an instant shader update (no re-bake); switching the HDRI re-bakes the IBL on a worker thread, so it never freezes the UI.

### Changed
* **Default shading is now PBR + IBL** (the "PBR" shade mode) instead of the 3-point-lit "Rendered" mode. The other shade modes are unchanged; the analytic key light still drives the PBR highlight, and the full key/fill/rim rig still drives the "Rendered" mode.
* **Default viewport framing.** A freshly loaded figure now sits centered and full-height in the view — the camera aims at mid-torso at a closer distance, instead of targeting the floor and pushing the figure high and far back.
* **Figure content-folder terminology.** The figure-import recovery flow now refers to a "Content Folder" (dialog titles, the "Locate Content Folder…" button, and messages) — clearer and free of third-party product branding.

### Fixed
* **Twist bones no longer bend.** The mid-limb "twist" joints (e.g. mid-femur, mid-forearm), which sit where a human has no real joint, are now locked to their axial-twist axis only — they can still twist to distribute limb rotation but can't fold the limb mid-bone.
* **Correct PBR key-light specular.** The analytic key light's specular used an over-darkened geometry term (roughness⁴ instead of roughness²); rough surfaces now get the right amount of specular shadowing.

## [0.3.0] - 2026-08-12
### Added
* **Rigged character figure import — the full pipeline.** PoseStudio can now import posable, morphable character figures from their native scene format (`.duf`/`.dsf` — a gzip-compressed JSON preset that references geometry, rig, skin-weight, morph, and UV data files spread across a content folder) and render them, textured, in bind pose. This is a large new subsystem (`src/viewport/import/figure/`), built as a Qt-free, **format-agnostic reader**: one reader handles many figure families and generations because the format is self-describing — geometry, bones, weights, morphs, and materials all come out of the files, so there is no per-figure branching. **File → Import → `.DUF (DUF File)`** opens it; a figure also loads by **double-clicking it in the Asset Manager grid**, from the command line / "open with", and a companion `.pose` file can be applied the same ways.
  * **Geometry + material zones:** polygons are triangulated and grouped per material zone, with the external UV set applied seam-aware. Physically-based materials carry a base color plus diffuse / normal / bump / roughness maps, and merge the `material_library` base a preset extends (so a preset that only *overrides* channels still resolves correctly). Transparency for the eye's clear shells (cornea / moisture) is keyed on the material's refraction weight, so the iris shows through.
  * **Character-shape morphs:** the preset's dialed control channels are walked through their driver formulas to the real head/body shape morphs, whose sparse deltas are **baked into the base vertices at import** — turning the generic base into the specific character (face + body). The character's overall height (a driven figure scale) is applied too.
  * **Joint-center adjustment:** the same shape morphs also carry driver formulas that shift each bone's rest position, so the **skeleton follows the character's new proportions** — posed limbs pivot at the right places and the joint gizmo sits on the body.
  * **Skeleton + GPU skinning:** the bone hierarchy and per-vertex top-4 skin weights are parsed and skinned on the GPU (linear-blend skinning through a per-model joint-matrix storage buffer). Posing is anatomically correct — each joint rotates in its own oriented frame and rotation order, so elbows/knees/shoulders bend about their true axes.
  * **Joint-driven pose correctives:** corrective morphs that fire as a function of bend angle to fix mesh crumpling ("candy-wrapper") at deep elbow/knee/shoulder/hip bends. They are discovered *structurally* (a morph driven by a joint rotation channel), so they work across figure generations regardless of file naming; each corrective's driver formula is translated into a small stack-program and re-evaluated from the live pose, re-morphing the affected mesh on the fly.
  * **Catmull-Clark subdivision:** the low-resolution base cage is smoothed into the render mesh (positions smoothed, UVs seam-preserving, skin weights blended) so limbs/torso/face read round rather than faceted. Because subdivision is a linear operator, each corrective's sparse deltas ride onto the dense mesh through the same stencils, so the runtime re-morph is unchanged.
  * **Skin shading:** cheap subsurface skin shading (wrap-lighting + a warm subsurface band), tangent-space normal-map support (a screen-space cotangent frame, no vertex tangents), and grayscale bump maps applied as a mip-stable texture-space perturbation — which is what gives the skin its surface grain.
  * **Build dependencies:** two more header-only libraries are fetched via `FetchContent` at pinned tags — **nlohmann/json** (JSON parsing, deliberately kept out of Qt so the importer core stays Qt-free) and **miniz** (gzip inflate for the compressed scene files). CMake now also enables the **C** language for miniz's C implementation sources.
* **Interactive posing UI.** An imported figure is posable directly in the viewport:
  * **Click-to-pose:** a left-click that lands on a joint selects it and enters posing (the drag rotates that joint); a click on empty space still orbits the camera.
  * **Rotate gizmo:** three axis rings (X/Y/Z) around the selected joint, drawn in the joint's own rotation frame; dragging a ring performs an axis-constrained rotation (including twist).
  * **Joint rotation limits:** each joint is clamped to its anatomical range of motion (read from the figure's per-axis rotation limits), so bends stay realistic — a knee can't hyper-extend, the neck won't over-rotate, etc.
  * **Pose undo / redo** (`Ctrl+Z` / `Ctrl+Y`) over committed pose edits.
  * **Pose save / load:** **File → Save Pose… / Load Pose…** round-trip the figure's joint rotations through a small plain-text `.pose` file; a `.pose` passed on the command line / "open with" applies onto the imported figure.
* **Viewport shader modes (a "shader picker").** A floating dropdown in the viewport's top-right corner switches between **twelve** shade modes instantly, with no pipeline swap: Rendered (skin/subsurface), **PBR** (physically-based — the photoreal mode), three Matcaps (Studio / Skin / Metal), Toon / Cel, Clay, Lighting-Only, Flat Shaded, Normals, Albedo (unlit), and UV Checker. The selector is a real menu, so it matches the app's menu styling exactly.
* **Anti-aliasing (MSAA).** The viewport renders with multisample anti-aliasing (up to 4×, device-dependent, with a single-sample fallback), so figure and model silhouettes are smooth instead of jagged.
* **Three-point studio lighting.** The scene is lit by a proper **key / fill / back (rim)** rig, world-fixed relative to the subject so lighting stays consistent as the camera orbits, giving imported figures dimensional, studio-portrait lighting. The PBR mode evaluates a full Cook-Torrance BRDF per light plus a hemisphere image-based ambient, a subsurface term for skin, and a fresnel back-rim, ACES-tonemapped.

### Changed
* **Content-folder resolution for figures.** The figure importer resolves a preset's cross-file references against the content-root folder(s): the folder auto-detected from the imported file's own location, **unioned** with any roots the user has configured. When a figure is browsed from a presets-only folder (with no co-located `data/` folder), the interactive import now offers a **"Locate Content Folder…"** prompt, remembers the chosen root, and retries — so those figures import instead of failing silently. A file that isn't a figure (pose / material / light presets share the extension) reports a clear message rather than doing nothing.
* **Skeleton overlay hidden by default.** Importing a figure no longer draws the bone cage over the character; the rotate gizmo is the visual affordance. Joints stay clickable (picking is independent of what's drawn), so a click on a joint still selects it and brings up the gizmo.
* **Menu styling refresh.** The menu-bar dropdown menus (and the viewport shader menu, which is itself a real menu) now share the Asset Manager's dark surface (`#252627`) and blue hover highlight (`#314D7A`), with rounded corners and no drop shadow.
* **Default viewport lighting upgraded** from a single directional key light to the three-point rig above; the mesh fragment shading (both the default Rendered mode and PBR) was reworked to use it.

### Fixed
* **Linux / single-config CMake builds no longer fail on the shader mirror step** — the post-build copy of the compiled shaders was copying the folder onto itself when the build and output directories coincide. (#22 — thanks @yash-jain221)

## [0.2.0] - 2026-06-24
### Added
* **3D Viewport (Vulkan):** Introduced the foundation of a real, Vulkan-backed 3D viewport (`src/viewport/`), replacing the static dark placeholder widget in the main window. The viewport hosts a custom `QWindow` (not Qt's `QVulkanWindow`) so the app owns the device, swapchain, and render passes directly, and renders an infinite floor grid plus imported meshes (see below) through a real orbit camera with mouse/wheel navigation.
  * **Qt / engine boundary:** The subsystem is split into a thin Qt-facing layer (`ViewportWidget`, `VulkanWindow` — the only files allowed to include Qt) and a Qt-free rendering core under `rendering/` and `scene/` (pure Vulkan + std + GLM), keeping the engine reusable and testable.
  * **Layered Vulkan lifetime:** `VulkanContext` (instance/device/queues/VMA allocator) is created once; `VulkanSwapchain` (images, shared depth buffer, render pass, framebuffers) is the resolution-dependent layer rebuilt on resize; `VulkanRenderer` owns per-frame state and drives acquire → record → submit → present, with coalesced resize handling.
  * **Infinite floor grid:** Drawn as a single full-screen quad whose fragment shader reconstructs the world point on the `y=0` plane per pixel, with anti-aliased lines via `fwidth` derivatives, distance fade, and correct `gl_FragDepth` so scene geometry occludes it (`scene/grid.{h,cpp}` + `grid.vert/frag`).
  * **Orbit camera:** A pure-GLM orbit `Camera` with Vulkan-correct clip-space conventions (`scene/camera.{h,cpp}`). Drags drive the camera only when the press began inside the viewport, so opening a modal dialog (e.g. the Import file picker) over the native child window can't leak a button-held move and snap the view.
  * **Graceful degradation:** If `QVulkanInstance::create()` fails, the viewport falls back to an inline message instead of preventing the app from launching.
* **Viewport object context menu (right-click → Delete):** Right-clicking a model in the 3D viewport now picks the object under the cursor (a camera ray vs. each model's bounding box) and opens a context menu; its first action, **Delete**, removes that model from the scene. Deletion waits for the GPU to go idle before freeing the model's buffers/textures so it's safe mid-session. Picking is bounding-box level for now (fine for selecting whole imported objects).
* **Import menu:** **File → Import** is now a submenu enumerating the planned model formats — `.ABC`, `.BVH`, `.DAE`, `.FBX`, `.GLB`, `.OBJ`, `.PLY`, `.STL`, `.USD` — with only `.OBJ (Wavefront)` enabled today; the rest are disabled placeholders that will light up as each importer lands.
* **OBJ model import + textured mesh rendering path:** The first working importer — **File → Import → `.OBJ (Wavefront)`** opens a file dialog and loads the model into the 3D scene, lit by a directional key light + ambient fill, with its **diffuse texture (MTL `map_Kd`)** mapped on and tinted by `Kd` (geometry with no texture/material falls back to a light neutral grey, `#D1D1D1`), sitting correctly on the floor grid with depth. This stood up the entire mesh-rendering path the viewport previously lacked:
  * **GPU resources:** `VulkanBuffer` (`rendering/vulkanbuffer.{h,cpp}`) and `VulkanTexture` (`rendering/vulkanimage.{h,cpp}`, an sRGB sampled image with a generated mip chain) — move-only VMA RAII wrappers — plus `submitImmediate` (`rendering/vulkancommands.{h,cpp}`), the shared one-shot graphics-queue submit used for every load-time upload/transition.
  * **Lit, textured mesh pipeline:** A `Scene` (`scene/scene.{h,cpp}`) owning the mesh pipeline, a per-frame camera/lighting UBO (descriptor set 0), a shared set-1 layout + 1×1 white fallback texture, and the imported `Model` list; an interleaved `Vertex` (pos/normal/uv) format; per-draw push constants (`model` + `baseColor`); per-material diffuse texture in set 1 (`albedo = baseColor * texture`). `PipelineConfig` gained vertex-input, descriptor-set-layout, and cull-mode knobs. Two-sided shading (normal flipped per `gl_FrontFacing`) so inconsistent OBJ winding still reads correctly.
  * **Codec stays out of the core:** the Qt-free `loadObj()` (`scene/objloader.{h,cpp}`, over tinyobjloader) de-indexes geometry, generates smooth normals when absent, groups by material, and resolves `map_Kd` paths (including the quoted, space-containing absolute paths some exporters emit); the **Qt layer decodes the image files via `QImage`** and hands raw RGBA8 down — so the renderer needs no image-codec dependency yet supports every format Qt's plugins do. A texture that can't be found or decoded logs a warning and falls back to the base color rather than failing the import.
  * **Command-line / "open with":** any `.obj` path passed as a launch argument is imported on startup (queued until the renderer is ready), so the app works as a drag-onto-exe / file-association target too.
  * **Import progress indicator:** interactive imports show a modal, staged progress dialog (reading file → decoding textures → uploading to GPU), shown immediately and kept up for the whole import so large models no longer freeze the window with no feedback. The work is still synchronous on the GUI thread; the dialog repaints between phases.
  * **Faster import (batched GPU uploads):** a model's mesh buffers and textures are now uploaded through a single batched command submission (`ImmediateBatch`) instead of a separate submit + GPU fence-wait per buffer and per texture (~3 blocking round-trips per material group). On models with many material groups this is the dominant import cost, so this is a large speed-up. Trade-off: staging buffers for the whole model are held in memory until the one submit completes.
  * Non-diffuse PBR maps (normal/metal/rough) are a later step — OBJ doesn't natively carry them.
* **Build: Vulkan, GLM, VMA & tinyobjloader dependencies:** `CMakeLists.txt` now requires the LunarG Vulkan SDK (`find_package(Vulkan REQUIRED)` plus a check for the `glslc` compiler) and fetches GLM (`1.0.1`), AMD's Vulkan Memory Allocator (`v3.1.0`), and tinyobjloader (`v2.0.0rc13`) header-only via `FetchContent` at pinned tags — a fresh clone needs only Qt + the Vulkan SDK, nothing vendored. GLSL shaders under `src/viewport/shaders/` are compiled to SPIR-V via `glslc` and mirrored next to the executable on every build. CMake minimum raised to 3.21.

### Changed
* **"Add Asset Folder" remembers its location:** The folder browser now opens in the parent directory of the last asset folder you added (e.g. add `D:\Content\MyLibrary` and next time it starts in `D:\Content`), instead of always resetting to your home folder. Persisted in Preferences, so it survives restarts, and shared by both entry points (the Asset Manager and Preferences → Assets). Falls back to home if the remembered folder no longer exists.
* **Import remembers its location:** File → Import's file browser now opens in the folder of the last model you imported (persisted in Preferences, so it survives restarts) instead of always resetting to Documents. Falls back to Documents if that folder no longer exists.
* **Asset Manager ignores `.mtl` files:** Wavefront `.mtl` material libraries are sidecar files that belong to an `.obj`, not assets in their own right, so they're no longer listed as separate items in the asset grid (nor do they count toward a folder's asset hit-state / search results). Handled via a shared "ignored sidecar extensions" set, so more such types can be added later.
* **Double-click an `.obj` to import it:** Double-clicking a `.obj` asset in the grid now imports it into the 3D viewport (via the same path as File → Import and command-line "open with"), instead of opening it in the OS default application. Other file types still open in their default app, and double-clicking a folder still navigates into it.
* **Splash/About overlay is now a top-level window:** `SplashOverlay` was reworked from a child widget into a frameless, translucent top-level window owned by the main window and positioned over it. This is required because the new viewport is a native child window (`createWindowContainer`), which composites on top of ordinary overlay widgets — a child overlay would be hidden behind the viewport. As an *owned* window (rather than a globally always-on-top one) it stacks above PoseStudio's own window/viewport but still yields to other applications when they take focus.
* **Cross-platform foundation hardening:** With the renderer taking shape, started making good on PoseStudio's fully-cross-platform goal (Windows/macOS/Linux), fixing portability issues before they calcify. Note that only the Windows/MSVC build has actually been exercised so far — the macOS/Linux paths are correct by construction but not yet built or run.
  * **macOS Vulkan via MoltenVK:** Vulkan device creation now enables the `VK_KHR_portability_subset` device extension whenever the physical device advertises it. This is mandatory on MoltenVK — the Vulkan-on-Metal layer macOS/iOS run Vulkan through — and a no-op on desktop Windows/Linux drivers, so the renderer can bring up a spec-conformant device on Apple hardware.
  * **Windows-only icon resource guarded:** `resources/PoseStudio.rc` (the executable-icon resource) is now added to the build only under `if(WIN32)`. It's meaningless to the Clang/GCC toolchains used on macOS/Linux, where listing it unconditionally broke CMake configuration.
* **User database relocated to the per-user app-data directory:** `posestudio.db` now lives in `QStandardPaths::AppDataLocation` (e.g. `%APPDATA%/PoseStudio` on Windows, `~/Library/Application Support/PoseStudio` on macOS, `~/.local/share/PoseStudio` on Linux) instead of next to the executable — an installed app's own directory is read-only on macOS/Linux, and writing there also breaks code signing. A one-time *move*-migration relocates any existing exe-adjacent database into the new location on first launch (copy-then-delete) so existing libraries, collections, and favorites are preserved; Factory Reset additionally clears any lingering legacy file so it can't resurrect wiped data. The application name is now set at startup so the data path resolves deterministically.
* **Source tree reorganized by subsystem:** `src/` is now split into one folder per area — `core/` (database, preferences manager), `shell/` (menu bar, splash/About overlay, Fusion theming), `assets/` (Asset Manager), and `preferences/` (the dialog + every panel) — alongside the existing `viewport/`, extending the folder-per-subsystem layout the viewport introduced. Only `main.cpp` and the cross-cutting `constants.h` remain at the `src/` root. Each subsystem folder is on the compiler include path, so the existing bare-name `#include`s still resolve unchanged — a pure organizational move with no behavior change.

### Added

* **Drag-and-Drop UX Enhancements:** * Replaced the per-item hover highlight with a precise, blue insertion drop-line indicator to clearly show where a dragged asset will land.

### Changed
* **Drag-and-Drop Code Refactor:** Generalized the hand-rolled grid drag-reorder mechanism (ghost thumbnail, drop-line indicator, edge auto-scroll) to be shared seamlessly between Favorites and Collections. This is now gated behind a single `isSortableView()` check, with previously Favorites-specific methods renamed to generic equivalents (e.g., `beginFavoritesDrag` renamed to `beginGridDrag`, `persistGridOrder()`, etc.).
* **Folder-to-Collection Refactor:** Completely changed the behavior of adding a folder to a collection. Instead of creating a folder shortcut, it now automatically creates a new sub-collection named after the target folder, populated exclusively with the direct assets inside that folder (ignoring subfolders and their contents).
* **Library Root Sorting:** Updated the sorting logic for top-level library roots (e.g., Maquettes, My 3D Library) to sort alphabetically by folder name, rather than by their database insertion order.
* **Repository Sync:** Fast-forwarded the local `main` branch to match `origin/main`, pulling in recent upstream features including nested sub-collections, library empty-state, factory reset, dialog theming, and documentation updates.
* **Context Menu Performance:** Massively improved the performance of the "Expand Branch" context menu action by batching UI repaints (`setUpdatesEnabled(false)`) and leveraging Qt's native `expandRecursively()` method, preventing application freezes on large directory trees.
* **Database Migration Refactor:** Consolidated the repeated "check `PRAGMA table_info`, then `ALTER TABLE ADD COLUMN`" boilerplate in `database.cpp` into shared `tableHasColumn()`/`ensureColumn()` helpers (the latter also handles one-time seed queries for backfilling existing rows), so future additive schema changes are a single one-line call instead of a copy-pasted block.

### Fixed
* **Asset Sort Order Persistence:** Fixed a root-cause bug where `buildAssetHits` grouped results by folder and returned them in hash-iteration order, destroying the database's visual sort order. It now builds a path-to-hit map and emits results in the strict input order.
* **Drag-and-Drop Reshuffling:** Fixed an issue where the asset grid would live-shuffle incorrectly mid-drag. The original item now stays in place during the drag, and the layout remains stable until the drop target is computed upon release.
* **Info Bar Formatting:** Corrected asymmetric padding and set explicit vertical alignment to perfectly center the text within the new Info Bar footer, adding appropriate spacing before the "Sortable" indicator.
* **Search Result Folder Naming:** Fixed an issue where adding a folder to a collection directly from search results incorrectly saved the full breadcrumb path (e.g., `Characters / Female / Hair`) instead of isolating just the leaf folder name (`Hair`).
* **Header Breadcrumb Clipping:** Increased the right-side padding margin (`kMargin` adjusted to 65px) in the asset window header to guarantee that the breadcrumb asset count suffix does not get clipped off-screen when the window is resized to be very small.
* **Breadcrumb "Open" Action:** Right-clicking the asset window header's breadcrumb now only enables "Open" when the click actually targets a clickable ancestor folder link; right-clicking the bright current-folder segment (which isn't a link) now correctly leaves it greyed out instead of re-opening the folder you're already in.
* **Preferences Tab List Row Height:** Preferences dialog nav items now get an explicit row size hint instead of relying on QSS `::item` padding alone, fixing an oversized hover/selection highlight that bled into neighboring rows.

### Removed
* **Tree Node Hit Counts:** Completely removed the numeric asset "Hit" counts (previously displayed in parentheses) from tree nodes to clean up the UI and eliminate the expensive, synchronous recursive disk/database scanning operations that were slowing down the application.
* **Header Asset Count:** Removed the blue `(x)` numeric count suffix from the Asset Panel Header title to simplify the UI and defer to the new Info Bar footer.
* **Folder Shortcuts Mechanism:** Completely abandoned and removed all code associated with the old folder shortcut feature, including deleting the `AssetCollectionFolders` table from the SQL schema, removing it from migration scripts, and eliminating related context menu actions.
