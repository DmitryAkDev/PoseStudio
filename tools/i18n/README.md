# UI translation process

PoseStudio's user interface is English in the source code; each language catalog
(`translations/ru.ts`, ...) is generated by an LLM from a fixed per-language system
prompt. The scripts below are manual tools: nothing in the build or ctest calls them,
and every catalog that ships has been read through by a human first.

## Files

| File | Purpose |
|---|---|
| `translate.py` | Self-contained translator: stdlib only, reads config and prompt from this directory |
| `dump.py` | Manual-review dump of a catalog (source -> translation pairs, control chars visible); the dump ends with a consistency audit; `--audit` runs that check alone and exits 1 on divergence |
| `clear.py` | Empties every `<translation>` in one catalog (keeps the XML structure) — for re-rolling it from scratch |
| `add_language.py` | One-shot language onboarding (CMake list + prompt template + .env + lupdate) |
| `llm_pool.py` | Shared pipeline infrastructure imported by `translate.py` (env loading, model pool, the chat/completions call) — stdlib only, no CLI logic |
| `.env` | Shared LLM model pool — `LLM_MODEL_<NAME>_API_BASE/_MODEL/_TEMPERATURE`. Must exist (create it from `.env.template`); machine-specific values never go into git |
| `.env.template` | Clean copy of the pool format |
| `locales/template.md` | Language-neutral English prompt template; `add_language.py` fills in the language name and code |
| `locales/<lang>/translator.md` | Per-language system prompt (output contract + domain context + terminology table) — the single source of translation style for that language |
| `locales/<lang>/.env` | Per-language model config: a full `LLM_MODEL_DEFAULT_API_BASE/_MODEL/_TEMPERATURE` set and/or `MODEL=<name>` to pick a pool entry by name (not committed) |
| `gold/` | Per-language gold sets (`<lang>.gold.tsv`): pinned source strings with the expected translation — the regression check for model/prompt drift, see `gold/README.md` |

## Model resolution

The language is inferred from the catalog file name (Qt convention: `ru.ts` → `ru`).
Config is loaded as top-level `.env` + `locales/<lang>/.env` overlay (the top-level
file must exist — create it from `.env.template`; machine-specific values never go
into git), then:

- prompt: `locales/<lang>/translator.md` (an explicit prompt file as a second argument always wins);
- model: `MODEL=` from the locale `.env` if present, otherwise the `DEFAULT` entry;
  `--model <name>` overrides both. No resolvable model = the language is skipped.
- hybrid reasoning models think by default: every label pays for a chain-of-thought
  pass (10-50x slower), and the CoT tends to override the terminology table with its own
  reasoning. `LLM_MODEL_<NAME>_NO_THINKING=1` in the model's `.env` sends
  `chat_template_kwargs: {"enable_thinking": false}` and skips the pass;
  for label translation the prompt carries all the context, so nothing is lost.

## Working on a catalog

```sh
# 1. New strings in the source? Regenerate the catalog skeleton first.
cmake --build build --target PoseStudio_lupdate -j4

# 2. Translate everything that is empty (idempotent; a few minutes).
python3 tools/i18n/translate.py translations/<lang>.ts

# 3. Automated audits: placeholders (%1, %2, ... must survive in every filled
#    entry) and consistency (one source -> one translation; exit 1 otherwise).
python3 tools/i18n/translate.py translations/<lang>.ts --check
python3 tools/i18n/dump.py translations/<lang>.ts --audit

# 4. Read the whole catalog once; fix style drift and lost accelerators by hand
#    directly in the .ts (\tDel and the like are part of the UI text).
python3 tools/i18n/dump.py translations/<lang>.ts --out /tmp/review.txt

# 5. Build the qm AND the app — the .qm is compiled into the binary as a Qt
#    resource, so lrelease alone changes nothing in the running app.
cmake --build build --target PoseStudio_lrelease -j4
cmake --build build --target PoseStudio -j4

# 6. Verify in the running app (menus, dialogs, tooltips; switch languages
#    via Preferences -> General and restart).
```

Useful one-offs: `translate.py <catalog> --dry-run` lists what would be translated
(no LLM calls); `--limit N` translates at most N entries; `dump.py <catalog> --empty`
is a progress check, `--context NAME` a slice.

## How the script behaves

- **Idempotent.** An entry is skipped when its translation is non-empty; a rerun makes zero LLM calls.
- **One request per string**, with the context class name and the translator comment — the model sees where the string lives.
- **HTML tokenization.** Tags in the source are replaced with neutral `{Tn}` tokens before the call and restored from the answer; if the model drops or invents a token, the entry is rejected and stays empty for the next run.
- **Placeholder guard.** An answer containing `%n` that is absent from the source is rejected.
- **Failure report.** Untranslated entries are listed at the end; the file is saved with everything that succeeded, so a rerun picks up the rest.
- **Deterministic normalization.** Before validation, the answer is repaired mechanically where LLMs tend to drift: literal backslash-t / backslash-n sequences become real control characters when the source carries them (menu shortcut labels), multi-line sources keep the full multi-line answer (no first-line truncation), and leading/trailing spaces are mirrored from the source onto the answer — such strings are fragments of concatenated tr() calls, so a missing edge space glues two words together at the join.
- **Line skeleton fitting.** A multi-line answer is pinned to the source's line structure: edge newlines are mirrored from the source, a collapsed blank line is re-expanded at the source's position, and surplus lines are merged into the last segment. An answer that cannot be fitted is rejected (stderr note) and stays empty for the next run.
- **Guards after normalization.** Exact `\t` / `\n` / `\r` counts versus the source, and non-word symbols (‹ › ° →) never fewer than in the source.

## Regenerating a catalog from scratch

The script only fills empty entries, so a new system prompt (or a model swap) does not
re-translate existing strings. To re-roll the whole catalog: clear every `<translation>`
text (keep the XML structure), then run a full pass.

```sh
python3 tools/i18n/clear.py translations/<lang>.ts
python3 tools/i18n/translate.py translations/<lang>.ts
```

A rerun with a different model produces different results (wording and terminology
drift), so after any full regeneration the catalog needs a fresh review pass
(consistency audit + manual reading) before it ships. `clear.py` asks for confirmation
before discarding existing translations (`--yes` skips the prompt).

## Adding a new language

```sh
python3 tools/i18n/add_language.py <lang> [model]
```

The script does every mechanical step:

- appends `<lang>` to `set(POSESTUDIO_I18N_LANGS ...)` in `CMakeLists.txt` — both build
  branches (lrelease targets, lupdate args, resource aliases, `qt_add_resources`) are
  generated from that list, so this is the only CMake edit that exists;
- creates `locales/<lang>/translator.md` from `locales/template.md` with the language
  name/code filled in (terminology table left as TODO);
- writes `MODEL=<model>` into `locales/<lang>/.env` (when a model is given) — if your
  model is not in the top-level pool, add its full `LLM_MODEL_DEFAULT_API_BASE/_MODEL/
  _TEMPERATURE` set to that file instead;
- reconfigures the build and runs `PoseStudio_lupdate`, which generates the empty
  `translations/<lang>.ts`.

Left for a human:

1. Fill the terminology table in `locales/<lang>/translator.md`.
2. Make sure `locales/<lang>/.env` points at a working model.
3. Add `{"<lang>", "<Endonym>"}` to `Constants::AVAILABLE_LANGUAGES` in `src/constants.h`
   (the Preferences -> General language picker is driven by that list). Translator
   loading in `src/main.cpp` is already generalized — any non-English code loads
   `:/translations/<lang>.qm`.
4. Full pass + `--check` + review, then build and verify in the app (see "Working on a
   catalog" above).
5. Bootstrap `gold/<lang>.gold.tsv` from that reviewed run — see `gold/README.md`
   ("Bootstrapping a new language").

Without the script, the whole CMake part is still just adding `<lang>` to the
`POSESTUDIO_I18N_LANGS` list.
